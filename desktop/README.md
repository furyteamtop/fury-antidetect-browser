# desktop — нативная оболочка (Tauri 2 + React)

Окно, соединение с сервером и сессия. Всё, что касается профилей, будет делать
агент ([docs/01](../docs/01-architecture.md)); здесь только то, чего не может
веб-страница.

## Два режима запуска

```bash
npm run dev     # браузер на localhost:5273, /v1 проксируется Vite
npm run app     # настоящее приложение (tauri dev)
npm run app:build   # .app + .dmg (macOS), .exe (Windows)
```

Браузерный режим оставлен намеренно: цикл «правка → перезагрузка» там занимает
секунды вместо десятков секунд на пересборку Rust. Это **инструмент разработки,
а не то, что поставляется** — в нём токен лежит в `localStorage`, а адрес сервера
задан в `vite.config.ts`. `api.ts` выбирает транспорт по наличию
`window.__TAURI_INTERNALS__`.

## Почему HTTP делает Rust, а не webview

Две причины, и обе видны только в собранном приложении:

1. **Иначе не работает вообще.** В собранном виде страница живёт на
   `tauri://localhost`, и относительный `fetch("/v1/me")` уходит в обработчик
   ассетов, а не на сервер. Чтобы ходить из webview, понадобился бы абсолютный
   URL **и** CORS на каждом self-hosted сервере. Запрос из Rust снимает вопрос:
   сервер может продолжать отказывать всем браузерным origin'ам.

2. **Токен не попадает в документ.** Сессии продлеваются при каждом запросе
   ([server/src/auth.rs](../server/src/auth.rs)), поэтому украденный токен живёт
   вечно, пока им пользуются. Такой ключ не должен лежать в хранилище, которое
   бэкапы и сборщики крешей копируют по умолчанию.

Команды намеренно узкие (`projects`, `profiles`, `lock`), а не общий
`request(method, path)` — иначе код бы переехал, а возможности остались те же.

## Что оболочка добавляет к браузерной версии

| | Браузер | Приложение |
|---|---|---|
| Адрес сервера | зашит в `vite.config.ts` | экран первого запуска, проверяется до сохранения |
| Токен | `localStorage` | память процесса + OS keychain |
| Имя машины в колонке блокировки | `navigator.platform` → `MacIntel` | реальное имя устройства |
| Второй запуск | вторая вкладка | фокусирует существующее окно |

Про keychain без преувеличений: на macOS у элемента есть ACL, привязанный к
подписи бинарника — но только когда у приложения появится стабильная подпись, а
её пока нет. На Windows Credential Manager шифрует блоб ключом пользователя, но
per-application ACL там нет вовсе. Это лучше, чем файл на диске, и не песочница.

## Чего здесь ещё нет

- **Агента.** Кнопка «Open» берёт лок и прямым текстом сообщает, что браузер не
  запущен. Ни строки, которая делает вид, что запустила.
- **Подписи и нотаризации.** Сборка не подписана, macOS будет ругаться при
  первом запуске ([docs/10](../docs/10-legal-licensing.md)).
- Разделов сайдбара из [docs/12](../docs/12-ui-reference.md) кроме проектов.

## Иконка

`src-tauri/icon.png` — мастер 1024×1024. После его замены:

```bash
npx tauri icon src-tauri/icon.png -o src-tauri/icons && rm -rf src-tauri/icons/android src-tauri/icons/ios
```

Мобильные наборы удаляются: продукт десктопный, а PNG-иконки Chromium рядом и так
занимают достаточно.
