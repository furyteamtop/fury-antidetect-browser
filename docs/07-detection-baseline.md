# 07 — Базовая линия детектируемости

Без этого документа проект превращается в «кажется, работает». Нужны **измеримые критерии**,
которые прогоняются на каждый ребейз ([03](03-chromium-fork.md)) и блокируют релиз.

## Правило №1

Тест-стенд собирается **до** написания первого патча. Сначала измеряем чистый Chromium
той же версии и получаем список того, что он выдаёт. Это baseline. Потом каждый патч
двигает конкретные метрики, и видно — двигает или нет.

Обратный порядок («напишем патчи, потом проверим») — способ полгода писать код, который
не работает.

## Что тестируем

### Уровень A — публичные чекеры (ручные и полуавтоматические)

| Сервис | Что даёт | Как используем |
|---|---|---|
| **CreepJS** | Самый строгий. Не «какой у вас отпечаток», а **«где вы врёте»**: сравнивает значения из разных источников, ловит расхождения между главным фреймом, воркером и iframe | Основной. Целевой результат: `lies: 0` |
| **BrowserLeaks** | Широкая диагностика по каждому API отдельно | Диагностика конкретного вектора |
| **Pixelscan** | Ищет несостыковки между заявленным и реальным железом, проверяет связку IP↔TZ | Проверка консистентности персоны |
| **BrowserScan** | Второй слой валидации, ловит то, что пропускают базовые | Финальная проверка перед релизом |
| **tls.peet.ws** / **browserleaks.com/tls** | JA3/JA4, HTTP/2 Akamai fingerprint | Снятие эталона и сверка |

**CreepJS — главный.** Он не считает «уникальность», он ловит ложь. Именно его логику
воспроизводят серьёзные антибот-системы: не «какое значение», а «согласуются ли значения
между собой».

### Уровень B — боевые антибот-системы

Публичные чекеры проходят все. Реальный вопрос — проходят ли антиботы.

| Система | Как тестировать |
|---|---|
| Cloudflare Turnstile / Bot Management | Публичные демо-страницы, страницы с включённым режимом |
| reCAPTCHA v3 | Демо-страница, смотрим score (цель: ≥ 0.7) |
| DataDome | Демо |
| PerimeterX / HUMAN | Демо |
| Akamai Bot Manager | Публичные сайты на Akamai |

Метрика — не «прошли/не прошли», а **процент успешных проходов из 100 запусков** на
разных резидентных IP. Один успешный запуск ничего не значит.

### Уровень C — собственный дифференциальный харнесс

Самое ценное и то, чего нет у конкурентов в открытом виде.

```
fury-detect-suite
  ├─ снять полный дамп отпечатка с настоящего Chrome (эталон)
  ├─ снять тот же дамп с Fury на той же персоне
  ├─ diff → список расхождений
  └─ красный, если расхождение не в белом списке ожидаемых
```

Дамп снимается **во всех контекстах**:

```
main frame
same-origin iframe
cross-origin iframe (OOPIF)
iframe[src=about:blank]
iframe[srcdoc]
Worker
SharedWorker
ServiceWorker
AudioWorklet
```

и по каждому собираются все ~200 значений из [02](02-fingerprint-surface.md).
**Любое расхождение между контекстами внутри одного профиля — красный флаг.**
Это самый частый способ спалиться и то, что первым делом проверяет CreepJS.

Плюс проверка стабильности: два запуска одного профиля должны дать **побитово
идентичный** дамп (кроме заведомо изменчивых полей вроде `performance.now()`).
Если canvas-хеш отличается между запусками — сайт видит «одно устройство, разное железо».

## Критерии релиза (release gate)

Релиз не выпускается, если хотя бы один пункт красный:

| # | Критерий | Порог |
|---|---|---|
| 1 | CreepJS `lies` | 0 |
| 2 | Расхождения между контекстами исполнения | 0 |
| 3 | Дифф с эталонным Chrome вне белого списка | 0 |
| 4 | Стабильность отпечатка между запусками | 100% |
| 5 | JA3/JA4 совпадает с настоящим Chrome той же версии | да |
| 6 | HTTP/2 Akamai fingerprint совпадает | да |
| 7 | Утечка реального IP при обрыве прокси | 0 из 50 попыток |
| 8 | WebRTC не показывает реальный IP | 0 из 50 |
| 9 | DNS-запросы мимо прокси | 0 |
| 10 | reCAPTCHA v3 score на резидентном IP | медиана ≥ 0.7 |
| 11 | Cloudflare Bot Management challenge | ≥ 90% проходов |
| 12 | Топ-30 реальных сайтов рендерятся без визуальных дефектов | 100% |

Пункт 12 отдельно важен: агрессивный canvas-шум ломает вёрстку и капчи. Регрессия
удобства — тоже регрессия.

## Что делать с результатом «прошли всё»

Ничего не значит навсегда. Антибот-системы обновляются, и алгоритмы детекта менялись
по нескольку раз за 2025-2026. Поэтому:

- прогон suite **по расписанию раз в неделю**, а не только на релиз;
- отдельный алерт на «вчера проходили, сегодня нет» — это сигнал, что кто-то из
  антиботов обновил проверки, и надо разбираться немедленно;
- публичная страница со статусом прогонов — для открытого проекта это лучший
  маркетинг и лучшая мотивация не запускать метрики.

## Реализация

`tools/detect-suite/` — Rust-бинарь, использует Local API агента и CDP.
Дампер отпечатка — один самодостаточный JS-файл `tools/detect-suite/probe.js`,
который исполняется в каждом контексте и возвращает плоский JSON.

Эталонные дампы настоящего Chrome по версиям и платформам хранятся в
`tools/detect-suite/baselines/<chrome-version>-<platform>.json` и обновляются
при каждом ребейзе.
