# 12 — UX-референс: разбор AdsPower

За образец интерфейса берём AdsPower. Он не самый сильный по отпечатку, но
**командная работа и повседневная эргономика у него лучшие на рынке** — и именно
это надо повторить, а потом улучшить в трёх местах, где у него нет решения.

Ниже разбор реального экрана «Профили» и выводы для Fury.

## Что устроено правильно и надо повторить

### 1. Список профилей — это и есть приложение

Нет дашборда, нет «домашней страницы», нет экрана приветствия. Открыл программу —
сразу таблица профилей. Всё остальное (группы, прокси, расширения, автоматизация) —
второстепенные разделы в сайдбаре.

Это правильно: пользователь заходит десять раз в день, чтобы открыть профиль.
Любой экран между запуском и списком — трение.

**Для Fury:** окно открывается на списке профилей последнего проекта. Никакого
онбординга после первого раза.

### 2. Основное действие продублировано в двух местах

Кнопка «Открыть» есть и в тулбаре (для выделенных), и в каждой строке справа.
Плюс контекстное меню «⋮» на строке для всего остального.

Не «избыточность», а разные сценарии: открыть один профиль → кнопка в строке;
открыть пачку → выделить чекбоксами и тулбар.

### 3. Тулбар массовых операций всегда на месте

Постоянная панель над таблицей: Открыть, RPA, синхронизатор, закрыть все,
экспорт, импорт, поделиться, удалить, «...». Не появляется/исчезает при
выделении — просто становится активной. Кнопки не прыгают, мышечная память
работает.

### 4. Колонка прокси показывает то, что нужно перед запуском

В одной ячейке: иконка типа прокси, флаг страны, IP, название страны. Оператору
надо **до** открытия профиля понять, тот ли выход. Не «прокси №4», а
реальный IP и гео.

### 5. Иконка ОС рядом с именем профиля

Значок платформы прямо в колонке имени — видно, какая ОС в отпечатке, не открывая
профиль. Мелочь, которая экономит клики каждый день.

### 6. «Последнее открытие» — полноценная колонка с сортировкой

Ключевая метрика для того, кто ведёт аккаунты: какие профили залежались.
Аккаунт, который не открывали два месяца, ведёт себя иначе, чем живой.
Сортировка по этой колонке — рабочий инструмент, а не украшение.

### 7. Квоты всегда видны в сайдбаре

Внизу постоянно: сколько профилей из лимита, сколько пользователей из лимита,
до какой даты активна подписка. Пользователь никогда не упирается в лимит
внезапно.

**Для Fury** биллинга нет, но принцип остаётся: показывать в сайдбаре
**число профилей, число участников и состояние связи с сервером**. Последнее
важнее всего — оператор должен видеть, работает ли он онлайн или на локальном
кэше ([06](06-profile-sync.md)).

### 8. Фильтр групп + поиск с сохраняемыми критериями

Слева дропдаун группы, справа поиск с иконкой расширенных фильтров
(«Поиск или новые критерии поиска»). При сотнях профилей это единственный
способ работать.

### 9. Корзина, а не удаление

Отдельный раздел «Корзина». Профиль с прогретым аккаунтом нельзя терять по
случайному клику.

### 10. Настраиваемые колонки

Иконка справа в шапке таблицы. У разных ролей разные потребности: менеджеру
нужны теги и группы, оператору — прокси и время последнего открытия.

## Структура навигации (берём почти как есть)

```
[Новый профиль]          ← primary-кнопка, самая заметная в окне

Профили                  ← активный по умолчанию
Группы
Прокси
Расширения
Корзина

АВТОМАТИЗАЦИЯ
  Синхронизатор          ← одновременное управление N окнами
  RPA                    ← no-code сценарии
  API                    ← локальный API (docs/05)

КОМАНДА
  Участники
  Права доступа
  Аудит-лог              ← у AdsPower слабее всего, см. ниже

──────────────────────
[состояние: онлайн/офлайн]
профили N · участники M
```

Одно отличие: у AdsPower иерархия — **группы**, плоские метки. У нас
**проекты** ([04](04-data-model-rbac.md)), потому что проект — единица выдачи
доступа. Группы внутри проекта оставляем как второй уровень для удобства.

## Три места, где надо сделать лучше

Это и есть продуктовая дифференциация. Всё остальное — паритет.

### A. Колонка блокировки — кто держит профиль прямо сейчас

У AdsPower профиль просто «открыт». У нас есть распределённый лок
([06](06-profile-sync.md)), и его состояние обязано быть в таблице:

```
🟢 свободен
🔵 открыт: Аня · MacBook-Anya · 14 мин
🟠 не синхронизирован — закрыт некорректно, есть локальные изменения
🔴 занят другим · [Снять принудительно]  ← только при manage_access
```

Без этого командная работа превращается в переписку «ты закрыл третий?».
Это самая частая операционная боль в агентствах, и её никто не закрыл.

### B. Бейдж консистентности отпечатка

Валидатор уже написан ([shared-rs/src/fingerprint.rs](../shared-rs/src/fingerprint.rs)).
Его результат — прямо в строке:

```
✓ консистентен
⚠ таймзона профиля не совпадает с гео IP     ← запуск блокируется
⚠ WebGL заявляет NVIDIA на macOS-персоне
```

Ни один продукт на рынке не показывает этого в списке. При этом именно
несостыковка, а не «плохой отпечаток», — причина большинства банов.

Правило из [01](01-architecture.md): красный бейдж = кнопка «Открыть»
неактивна с объяснением. Не предупреждение, которое проматывают.

### C. Счётчик профилей на одном IP

В колонке прокси: `RU · 46.x.x.x · ⚠ 4 профиля`. Несколько аккаунтов с одного
IP — классический признак фермы для антифрода. AdsPower это допускает молча.

## Что не копируем

- **Cloud Phone и облачные профили.** Требует парка машин, несовместимо
  с бесплатной моделью ([08](08-competitors.md)).
- **RPA-конструктор в v1.** Local API закрывает потребность для тех, кто умеет
  писать код. Визуальный конструктор — большой отдельный продукт.
- **Реферальные баннеры и апселлы в сайдбаре.** Продавать нечего.

## Права доступа отражаются в UI

UI скрывает недоступное, но это **презентация, а не защита** — enforcement
в [rbac_guard.rs](../server/src/rbac_guard.rs) и в самом ядре, в патчах, которые
читают флаги запуска: [0302](../core/patches/0302-devtools-lock.patch) для
`lock_devtools`, [0303](../core/patches/0303-data-export-lock.patch) для
`lock_data_export`.

Здесь раньше было написано «enforcement … в флагах запуска (launcher.rs)», и это
была ровно та ошибка, которую эти два патча закрыли: launcher.rs толкал
`--fury-lock-devtools` и `--fury-lock-data-export` при каждом ограниченном
запуске, а grep по `core/src` не находил ни одного вхождения. Обе «технические»
блокировки были скрытыми кнопками — оператор, которому запрещено уносить данные
профиля, открывал DevTools и читал оттуда cookies. Флаг — это просьба; запретом
он становится там, где его читают.

| Право отсутствует | Что видит пользователь |
|---|---|
| `reveal_secrets` | Прокси как `res-***.provider.net · GB`, пароли как `••••` без кнопки показать |
| `export_cookies` | Нет кнопок экспорта и «поделиться», в меню строки они отсутствуют |
| `edit_fingerprint` | Редактор отпечатка открывается только для чтения |
| `delete_profile` | Кнопка удаления отсутствует, не «выдаёт ошибку при клике» |
| `manage_access` | Нет раздела «Права доступа», нет «Снять блокировку принудительно» |

Отдельно про CDP, и это не про прятание в UI. У оператора без `export_cookies`
CDP не выдаётся вовсе: сервер считает `deny_cdp = !export_cookies`
([rbac.rs:171-181](../shared-rs/src/rbac.rs)), и лаунчер тогда просто не кладёт
`--remote-debugging-port` в argv ([launcher.rs:196-202](../agent/src/launcher.rs)).
Прятать «токен локального API для этого проекта», как было записано здесь
раньше, защитой быть не могло: токен один на машину и лежит в файле `api-token`
рядом с базой агента, режим 0600 ([http.rs:47-74](../agent/src/http.rs)).

## Технические решения по UI

- **Tauri 2 + React + TypeScript.** Инсталлятор ~10 МБ против ~120 у Electron,
  а рядом уже лежит 200-МБ Chromium.
- **Таблица пока не виртуализована.** `@tanstack/react-virtual` в
  [desktop/package.json](../desktop/package.json) нет, а
  [ProfileTable.tsx](../desktop/src/components/ProfileTable.tsx) рендерит
  `profiles.map(...)` целиком — все строки сразу. Решение остаётся прежним:
  пагинация в 2026 — компромисс от бессилия, виртуальный скролл на 5000 строк
  работает без неё. Но на сегодня это план, а не свойство сборки, и на
  нескольких тысячах профилей это станет заметно раньше всего остального.
- **Тема по умолчанию системная, не тёмная.** `useTheme()` стартует с `"system"` и разрешает её через `prefers-color-scheme` ([theme.ts:6,20,29](../desktop/src/theme.ts)), так что на светлой macOS приложение светлое. Хранится буквальный выбор из трёх — `system`, `dark`, `light`, — чтобы «системная» шла за десктопом на закате. Довод в пользу тёмной по умолчанию (в инструменте сидят по 10 часов) не отменён, он просто не реализован.
- **Состояние берётся поллингом, не подпиской.** `setInterval` на 5 секунд
  перечитывает профили, проекты и состояние агента
  ([App.tsx:149-156](../desktop/src/App.tsx)) — включая shell_state, потому что
  агент, умерший при открытом приложении, иначе оставлял предупреждение на
  экране навсегда. IPC-подписка остаётся тем, чего хочется: статус лока и
  запущенности меняется часто, и пятисекундная задержка в командном режиме
  видна. Сегодня таблица обновляется опросом.
