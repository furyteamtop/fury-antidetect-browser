# 09 — План работ

Фазы, у каждой — критерий выхода. Фаза не считается закрытой, пока критерий не выполнен
измеримо, а не «вроде готово».

## Фаза 0 — Стенд измерений (2-3 недели)

Первое, что делается. Без этого дальше работать вслепую.

- [x] `tools/detect-suite/probe.js` — дампер ~250 значений отпечатка
- [x] Прогон пробы в Worker и четырёх видах iframe со сравнением расхождений
- [x] `probe.html` — снятие дампа из любого браузера, включая AdsPower
- [x] `collector.py` — приём дампов в `baselines/` одной кнопкой
- [x] `fury-detect diff` — режимы identity и spoof, разделение value / behaviour
- [x] `fury-detect gate` — 13 проверок на внутренние противоречия, exit code для CI
- [x] `capture-chrome.sh` — снятие эталона без единого клика, на чистом профиле
- [x] **Эталон настоящего Chrome 150 на macOS arm64 снят, gate откалиброван: 13/13**
- [ ] Прогон в SharedWorker, ServiceWorker, AudioWorklet и cross-origin OOPIF
- [ ] Эталон Chrome на Windows 11 x64
- [ ] Снять дампы AdsPower и Camoufox для сравнения с рынком
- [ ] Собрать **чистый** Chromium текущего stable, снять дамп, получить diff с эталоном

**Критерий выхода:** есть отчёт «чистый Chromium отличается от настоящего Chrome в N
местах» с конкретным списком. Этот список — ваш реальный объём работы, а не догадки.

Побочная польза: список сразу покажет, сколько расхождений даёт отсутствие проприетарных
кодеков и Widevine — и это заставит решить вопрос из [10](10-legal-licensing.md) в начале,
а не в конце.

## Фаза 1 — Инфраструктура форка (3-4 недели)

- [ ] `core/build/fetch.sh` — depot_tools, пин версии, `gclient sync`
- [ ] `core/args/{windows,macos-arm64,macos-x64}.gn` с `proprietary_codecs = true`
- [ ] Первая успешная сборка на своём железе, Windows + macOS
- [ ] Патч `0001` — доставка конфига отпечатка в browser process и **во все рендереры/воркеры**
- [ ] Патч `0900` — брендинг, отключение Google-сервисов
- [ ] `core/build/{apply,refresh,rebase}.sh` — управление серией патчей
- [ ] CI на self-hosted runner: сборка по расписанию + прогон detect-suite

**Критерий выхода:** можно положить JSON в конфиг, запустить браузер, и одно тестовое
значение (например `navigator.hardwareConcurrency`) подменяется **одинаково во всех
контекстах исполнения**, включая Worker и cross-origin iframe.

Это узкое место всего проекта. Если патч `0001` сделан правильно, остальные 80 патчей —
механическая работа. Если нет — все они будут протекать.

## Фаза 2 — Векторы отпечатка (8-12 недель)

По порядку убывания важности. Каждый пункт = патч + запись в базе персон + тест в suite.

Приоритет 1 — то, что проверяют все:
- [ ] `0010-0011` navigator + userAgentData + Client Hints (один источник правды!)
- [ ] `0020` screen/window, включая дельту `outer-inner` и ширину скроллбара
- [ ] `0030` canvas noise
- [ ] `0031` WebGL параметры и шум
- [ ] `0080` timezone через ICU + Intl
- [ ] `0200-0220` TLS/JA3, HTTP/2 SETTINGS, порядок заголовков
- [ ] `0300` следы автоматизации

Приоритет 2 — то, что отличает от середины рынка:
- [ ] `0032` **WebGPU** adapter info + limits + features
- [ ] `0040` audio noise
- [ ] `0050` фильтр font fallback (не просто список)
- [ ] `0070` политика WebRTC
- [ ] `0090` согласованность Permissions API
- [ ] `0100` CSS media features

Приоритет 3:
- [ ] `0060` mediaDevices с солью
- [ ] `0110` os_crypt ключ из DEK (нужно для переносимости бандлов)
- [ ] speechSynthesis voices, performance.memory, stack trace format

**Критерий выхода:** release gate из [07](07-detection-baseline.md) зелёный по пунктам 1-9.

## Фаза 3 — База персон (параллельно с фазой 2, 4-6 недель)

- [ ] `shared/persona.schema.json`
- [ ] 30-50 персон вручную с реальных машин: Windows 11 и macOS, разные GPU и разрешения
- [ ] Генератор: `seed → persona → полный конфиг`, детерминированный
- [ ] Валидатор консистентности: ловит «macOS + NVIDIA», «ru-RU + America/New_York»,
      «8 ГБ памяти + 32 ядра» и прочие невозможные комбинации
- [ ] Веса персон по реальному распределению; персоны с `weight < 0.005` не выдаются авто

**Критерий выхода:** сгенерированный из случайного seed профиль проходит Pixelscan
и CreepJS без замечаний о несостыковках, 20 из 20 раз.

## Фаза 4 — Продуктовый слой (8-10 недель, параллельно с 2-3)

Не зависит от готовности ядра — можно вести другими руками.

- [ ] `server`: схема БД, миграции, auth, RBAC, RLS, аудит
- [ ] `server`: API проектов/профилей/прокси, лок, presigned URL для бандлов
- [ ] `agent`: launcher, vault, sync
- [ ] `agent`: **relay** — HTTP/SOCKS5 с авторизацией, удалённый DNS, kill-switch
- [ ] `agent`: чекер прокси с офлайн GeoIP
- [ ] `agent`: Local API + CDP endpoint
- [ ] `desktop`: список профилей, редактор отпечатка, менеджер прокси, участники и права
- [ ] Массовые операции, импорт CSV, импорт cookies
- [ ] Хранилище кредов с TOTP

**Критерий выхода:** два человека на двух машинах работают с одним проектом; один
не может увидеть пароль и выгрузить cookies; попытка одновременного запуска
одного профиля отклоняется.

## Фаза 5 — Дистрибуция (3-4 недели)

- [ ] macOS: universal binary, Developer ID, нотаризация, entitlements для хелперов Chromium
- [ ] Windows: EV code signing, инсталлятор
- [ ] Автообновление отдельно для оболочки и для ядра (ядро 200 МБ — только дифф-апдейты)

**Критерий выхода:** человек со стороны скачивает, устанавливает без предупреждений
ОС, поднимает свой сервер по инструкции и запускает первый профиль. Проверяется
на живом человеке, не на себе.

## Сводка по срокам

| Фаза | Длительность | Можно параллелить |
|---|---|---|
| 0 — стенд | 2-3 нед | — |
| 1 — инфра форка | 3-4 нед | после 0 |
| 2 — векторы | 8-12 нед | с 3 |
| 3 — персоны | 4-6 нед | с 2 |
| 4 — продукт | 8-10 нед | с 1-3, другими людьми |
| 5 — дистрибуция | 3-4 нед | конец |

Критический путь: 0 → 1 → 2 → 5 ≈ **17-23 недели**, то есть **4-6 месяцев** при
условии, что фаза 4 идёт параллельно другими руками.

Один человек последовательно — 9-12 месяцев, и с постоянным риском, что ребейзы
съедят всё время до того, как продукт будет готов.

## Минимальный состав

| Роль | Загрузка | Зачем |
|---|---|---|
| C++ / Chromium | 1 фултайм, желательно 2 | Фазы 1-2 + бессрочные ребейзы |
| Rust (agent + server) | 1 фултайм | Фазы 4 |
| Frontend (React) | 0.5-1 | Фаза 4 |
| DevOps / билд-инфра | 0.5 | Фазы 1, 5 |

Один C++-инженер — узкое место и single point of failure: он же делает патчи, он же
каждые 4 недели ребейзит. При его выпадении проект встаёт.
