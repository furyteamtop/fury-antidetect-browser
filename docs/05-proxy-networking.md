# 05 — Прокси и сеть

## Зачем нужен локальный релей

Chromium нельзя просто отдать прокси клиента. Причины, по каждой из которых уже нужен релей:

1. **Chromium не поддерживает авторизацию в SOCKS5.** Флаг `--proxy-server=socks5://user:pass@host`
   молча игнорирует креды. Работает только SOCKS5 без авторизации — а таких прокси на рынке
   почти нет.
2. **HTTP-прокси с авторизацией вызывает диалог** ввода логина/пароля, который надо
   перехватывать через CDP — то есть держать CDP-подключение к профилю, который должен
   быть чистым от следов автоматизации.
3. **Креды прокси не должны попадать в браузер.** Иначе сотрудник с доступом к профилю
   вытаскивает прокси организации.
4. **DNS.** Без релея Chromium может резолвить имена локальным резолвером → DNS-утечка,
   провайдер и сайт видят рассинхрон между гео DNS и гео IP.
5. **Точка контроля утечек** — единственное место, где можно гарантированно обрубить
   всё, что идёт мимо прокси.

Итог: браузер всегда запускается с `--proxy-server=http://127.0.0.1:<port>`, где `<port>` —
персональный порт этого профиля.

## Устройство релея

```
Chromium ──HTTP/CONNECT──► relay (127.0.0.1:P) ──► upstream (HTTP/SOCKS5/SSH)
                              │
                              ├─ авторизация в upstream
                              ├─ DNS: только удалённый резолв (SOCKS5h / CONNECT по имени)
                              ├─ kill-switch: upstream упал → рвём всё, не пускаем напрямую
                              ├─ фильтр: блок исходящего UDP мимо прокси (WebRTC/STUN)
                              └─ счётчики: трафик, RTT, ошибки → в UI
```

Поддерживаемые upstream:

| Тип | Примечание |
|---|---|
| HTTP / HTTPS | С Basic и Digest авторизацией |
| SOCKS5 / SOCKS5h | С авторизацией username/password. `h` = удалённый DNS, режим по умолчанию |
| SSH-туннель | `ssh -D`, для тех, у кого есть свой сервер |
| Ротационные по ссылке | URL смены IP + политика: при старте / по таймеру / вручную |

**Kill-switch обязателен и включён всегда.** Если upstream отвалился, релей не должен ходить
напрямую ни при каких условиях. Один запрос с реального IP убивает аккаунт, который вели
полгода. Поведение при обрыве: рвём все соединения, показываем баннер в UI, ждём
восстановления, не пропускаем ни байта.

## Проверка прокси

Перед запуском профиля и по кнопке в UI:

```
GET через прокси → сервис определения IP
  ↓
IP, ASN, страна, регион, город, таймзона, ISP
  ↓
классификация: datacenter / residential / mobile / hosting / vpn / tor
  ↓
fraud score (внешний сервис, опционально и отключаемо)
  ↓
проверка на публичных чёрных списках
  ↓
RTT, скорость
```

Результат кэшируется на профиль. Если у профиля включены `auto_timezone` / `auto_geo` /
`auto_locale` — значения выводятся отсюда и вписываются в конфиг отпечатка.

**Жёсткое правило:** если таймзона профиля не совпадает с гео IP — запуск блокируется
с явным объяснением. Это самый дешёвый детект в индустрии, и «просто предупредить»
недостаточно: пользователи проматывают предупреждения.

Для self-hosted проекта важно, чтобы определение IP работало **без обязательных внешних
платных сервисов**. Базовый режим — свой лёгкий эндпоинт (эхо IP) + офлайн-база
MaxMind GeoLite2 / DB-IP на стороне агента. Fraud score — опциональная интеграция,
которую пользователь включает своим ключом.

## Защита от утечек — три рубежа

Утечка реального IP — главный способ потерять аккаунт. Дублируем защиту:

### Рубеж 1: ядро

- Политика WebRTC (`fake` по умолчанию): host-кандидаты подменяются на правдоподобную
  приватную сеть, srflx — на IP прокси.
- QUIC отключён (иначе UDP пойдёт мимо HTTP-прокси).
- Отключены сервисы, ходящие в сеть мимо профильного прокси: Safe Browsing, обновления
  компонентов, Google-сервисы, `chrome://` телеметрия, DNS-prefetch к своим резолверам,
  Network Time.

### Рубеж 2: релей

- Все TCP-соединения только через upstream, kill-switch.
- DNS только удалённый. Локальный резолв запрещён.
- UDP не проксируется вообще (кроме случая, когда upstream — SOCKS5 с UDP ASSOCIATE
  и пользователь явно это включил).

### Рубеж 3: ОС (опционально, «параноидальный режим»)

Правило файрвола, разрешающее процессу ядра исходящие соединения **только** на
`127.0.0.1:<port>`. На macOS — `pf` anchor, на Windows — правило WFP по пути к бинарю.
Требует прав администратора, поэтому опция, а не дефолт. Но это единственный рубеж,
который держит даже если в ядре нашлась дыра.

## Привязка прокси

- Прокси — сущность организации, лежит в общем пуле.
- Может быть привязан к проекту (тогда виден только в нём) или общий для организации.
- Один прокси на один профиль — дефолт. Разрешить один прокси на несколько профилей
  можно, но UI обязан предупредить: несколько аккаунтов с одного IP — типовой признак
  фермы для антифрода. Показываем счётчик «профилей на этом IP».
- Креды прокси видны только при праве `reveal_secrets` ([04](04-data-model-rbac.md)).

## Local API для автоматизации

`127.0.0.1:35000`, токен из настроек агента.

```
GET  /v1/profiles                      список доступных
POST /v1/profiles/{id}/start           → { ws_endpoint, debug_port, pid }
POST /v1/profiles/{id}/stop
GET  /v1/profiles/{id}/status
POST /v1/profiles/{id}/proxy/rotate    сменить IP у ротационного прокси
```

`ws_endpoint` подключается напрямую в Puppeteer/Playwright:

```js
const browser = await puppeteer.connect({ browserWSEndpoint: wsEndpoint });
```

Выдаётся только если у пользователя есть право `export_cookies` — потому что через CDP
можно вытащить всё. Без права `start` вернёт `403` с пояснением.
