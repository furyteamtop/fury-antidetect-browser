# 15 — Установка

Для человека, который ничего не собирал. Сборка из исходников — это
[03](03-chromium-fork.md) и README; здесь предполагается, что у вас есть
компьютер и браузер, и больше ничего.

Fury — это **две загрузки**, и об этом стоит знать заранее, иначе вторая
выглядит как ошибка:

| | что это | размер |
|---|---|---|
| **Fury** | приложение: профили, прокси, персоны, команда | ~12 МБ |
| **Fury core** | сам браузер — форк Chromium | ~134 МБ |

Они разделены, потому что живут врозь. Приложение меняется еженедельно, ядро —
когда выходит новый Chromium, раз в шесть недель. Вместе они означали бы 134 МБ
загрузки из-за сдвинутой кнопки. И это сохраняет подпись приложения: ядро,
записанное внутрь подписанного бандла, ломает его печать, после чего macOS
говорит, что приложение **повреждено** — и человек идёт искать битую загрузку
вместо того, чтобы искать нас.

## macOS

### 1. Приложение

Скачайте `fury-<версия>-macos-<арх>.tar.xz` со страницы
[Releases](https://github.com/furyteamtop/fury/releases). `арх` — это `arm64`
для любого Mac на Apple silicon (M1 и новее) и `x86_64` для Intel; если не
уверены,  → «Об этом Mac» покажет.

Распакуйте и перетащите **Fury.app** в `/Applications`.

### 2. Ядро браузера

Скачайте `fury-core-<версия>-macos-<арх>.tar.xz` оттуда же. Затем в Терминале:

```bash
/Applications/Fury.app/Contents/MacOS/fury-agent install-core ~/Downloads/fury-core-*.tar.xz
```

Это единственная команда, которая требует терминала, и она делает три вещи,
которые вручную легко сделать неправильно: распаковывает бандл, сохраняя
симлинки, из которых собран macOS-фреймворк, снимает карантинный флаг, который
поставил ваш браузер при скачивании, и — главный шаг — **запускает браузер один
раз и проверяет, что он стартует**. Если напечаталась версия, ядро установлено:

```
installed Fury 150.0.7871.187
  /Users/you/Library/Application Support/Fury/core.bundle/Fury.app/Contents/MacOS/Fury
```

Спросить, что установлено, можно в любой момент:

```bash
/Applications/Fury.app/Contents/MacOS/fury-agent install-core
```

### 3. Запустите

Откройте Fury из «Программ». Ни аккаунта, ни регистрации, ни сервера: работает
сразу, всё остаётся на этой машине.

Командная работа — общие профили, общий пул прокси, доступ по проектам — в
**Настройки → Команда**, там же создаётся аккаунт и там же лежит инструкция по
поднятию своего сервера. Это решение можно принять позже или не принимать вовсе.

### Проверить, что скачалось

У каждого релиза есть файл `SHA256SUMS`. Скачайте его рядом с архивами и:

```bash
shasum -a 256 -c SHA256SUMS
```

Две строки `OK` означают, что файлы те самые, что были опубликованы.

### Если macOS отказывается открывать

Приложение подписано и нотаризовано, так что должно открыться. Если нет:

**«Fury нельзя открыть, так как разработчик не может быть проверен».** Загрузка
пришла без нотаризационного тикета — обычно это значит, что она не со страницы
Releases. Скачайте оттуда.

**«Fury повреждён и должен быть перемещён в Корзину».** Это почти никогда не
битый файл. Это значит, что подпись бандла больше не соответствует содержимому —
чаще всего потому, что внутрь `Fury.app` что-то добавили или из него что-то
удалили. Удалите и распакуйте загрузку заново.

**Ядро, собранное самостоятельно, не запускается** с сообщением про *Team IDs*.
Это устройство подписи, а не сломанная сборка; разбор целиком —
в [tools/release/sign-core.sh](../tools/release/sign-core.sh).

## Linux

Готовой сборки пока нет. Приложение и агент собираются за минуты:

```bash
cargo build --release
cd desktop && npm install && npm run app:build
```

Ядро придётся собрать из исходников ([03](03-chromium-fork.md)) — первый раз
около шести часов. Релиз ядра под Linux будет; препятствие не техническое, нужна
машина, которая прогонит сборку.

## Windows

Пока нет. Сказано прямо, а не «скоро»: патчи не зависят от платформы, агент и
оболочка переносимы, но ядро под Windows никто не собирал и не измерял, а
выпускать неизмеренное — ровно то, чего этот проект не делает.

## Где что лежит

Всё, чем владеет Fury, под одной директорией, поэтому «сделать бэкап» и «удалить
всё» — по одной операции:

```
~/Library/Application Support/Fury/
  fury.db          профили, прокси, персоны, проекты
  profiles/        данные браузера по профилям — куки, вкладки, закладки
  core.bundle/     установленный браузер (пакет, чтобы в поиске
                   был один Fury, а не два)
```

`FURY_HOME` переносит это куда угодно — на внешний диск или в шифрованный том.

Удалить Fury полностью: стереть эту директорию и `/Applications/Fury.app`.
Больше ничего никуда не пишется, и ничего не остаётся ни на одном сервере,
который вы не подняли сами.

## Обновление

Скачайте и распакуйте новое приложение поверх старого. Для нового ядра запустите
`install-core` с новым архивом — он проверяет, что новое ядро стартует, прежде
чем заменить имеющееся, так что битая загрузка оставит вас с рабочим браузером,
а не без браузера.

## Автообновление

Его нет, и это осознанный пробел, а не недоделка. Апдейтер — это канал, который
лезет в анти-детект браузер снаружи, по расписанию, с адреса, который не является
прокси профиля. Сделать такой канал, не ослабив то, что он обновляет, требует
большей аккуратности, чем на это пока потрачено; до тех пор честная позиция —
вы обновляетесь тогда, когда решите. Что должен уметь хороший апдейтер —
в [09](09-roadmap.md).
